# QTA V2 量化研究与个人交易复盘平台 PRD

> 状态：`DECISION / FROZEN FOR IMPLEMENTATION`
>
> 版本：v1.0  
> 冻结日期：2026-08-15  
> 产品范围：A 股优先；港股、美股保留现有行情能力，待各自数据口径和交易日历完成设计后扩展
>
> 市场研究详细图形、指标和数据方案：`QTA_V2_INSTITUTIONAL_MARKET_RESEARCH_DESIGN.md`

> 冻结说明：本文冻结产品定位、一级信息架构、金融语义边界、数据职责、建设顺序和验收方向。
> 外部 Provider 权限、资金流来源和具体阈值必须在 MR-0 PoC 与任务契约中验证，属于实施门禁，
> 不得由实施者自行改写产品结论。本文不代表任何 V2 功能已经实现或验收。

## 1. 文档目的

本 PRD 重新定义 QTA 的产品主线，纠正当前以采集配置、单证券图表和薄榜单为中心的产品形态。

QTA V2 的目标不是复制通达信，也不是堆叠技术指标，而是建立以下闭环：

```text
全市场数据资产
    → 市场资金与板块轮动研究
    → 可解释候选股票池
    → 规则和策略的历史验证
    → 人工交易计划与实际成交
    → 盈亏、策略和操作纪律复盘
```

## 2. 背景与问题

### 2.1 当前问题

1. 当前市场雷达主要使用排行样本和价格相对强弱，无法证明全市场资金方向。
2. 当前历史数据不足，缺少完整证券池、权威行业分类、历史行业成分和长期资金流序列。
3. 当前一级导航按已开发功能平铺，不能围绕“研究、验证、交易、复盘、数据运维”形成工作空间。
4. 行情工作台和行情资产是数据运维工具，却占据主要导航位置。
5. 量化研究尚未形成股票池、因子、信号、回测、组合和实验记录链路。
6. 部分指标名称混淆了资金金额、资金强度、成交活跃度和价格表现。

### 2.2 核心产品问题

QTA V2 必须让用户依次回答：

1. 今天市场是否适合参与？
2. 交易活动和主动买盘集中在哪里？
3. 这种方向是当日脉冲还是持续轮动？
4. 该板块内部哪些股票值得进一步研究？
5. 这套选择规则在历史上是否稳定有效？
6. 我的实际盈亏来自市场、策略、选股、时机、仓位还是执行纪律？

## 3. 产品定位

### 3.1 定位

QTA V2 是个人使用的市场研究、量化验证和交易复盘平台。

### 3.2 产品原则

- `DECISION`：市场研究结论必须基于已落库并通过质量校验的数据，不在页面加载时临时拼接 Provider 响应。
- `DECISION`：任何资金指标必须保留供应商、口径、时间窗口、币种和数据覆盖范围。
- `DECISION`：默认页面面向金融初学者，显示金额、排名、变化和自然语言解释；复杂公式进入指标详情。
- `DECISION`：不使用来源不明的综合评分。必须展示综合结论时，应同时展示组成证据。
- `DECISION`：行业、概念、ETF 使用不同聚合语义，不允许静默混算。
- `DECISION`：研究和回测必须遵守 point-in-time 原则，避免未来函数和幸存者偏差。

### 3.3 非目标

- 不建设自动下单和券商交易执行系统。
- 不以复刻专业看盘软件全部指标为目标。
- 不在 V2 MVP 建设高频 Tick 全市场数据库。
- 不在缺少真实资金数据时用价格涨跌冒充资金流。
- 不把概念板块的重叠成交额相加后宣称为全市场总额。

## 4. 用户与核心场景

### 4.1 用户

当前主要用户为一名希望逐步建立量化能力的个人投资者，具备交易经验，但不是专业金融从业者。

### 4.2 核心场景

#### 场景 A：盘后判断市场方向

用户在收盘后进入市场研究，判断市场流动性、资金偏好、持续性和风险状态。

#### 场景 B：从板块找到候选股票

用户从行业资金和轮动进入板块详情，再通过流动性、相对强弱和量价条件形成候选池。

#### 场景 C：验证一个交易想法

用户选择研究模板，定义股票池、条件和持有周期，使用历史数据判断规则是否稳定。

#### 场景 D：执行并复盘个人交易

用户把候选转为人工交易计划，记录实际成交，盘后区分策略问题与执行问题。

#### 场景 E：维护数据资产

用户查看数据覆盖率、水位、失败任务、历史缺口和 Provider 权限，不需要通过服务器日志判断数据是否正常。

## 6. 金融语义冻结

### 6.1 成交额

某个时间窗口内的成交金额，回答“交易活动发生在哪里”，不代表资金净流入。

### 6.2 成交额占比

```text
板块成交额占比 = 板块成交额 / 同市场全市场成交额
```

回答该板块占据了多少市场交易注意力。行业占比可以使用互斥行业分类汇总；概念板块因成分重叠不能汇总为 100%。

### 6.3 供应商口径资金净额

由数据供应商根据主动买卖、订单大小等规则计算的净流入/净流出。

`DECISION`：字段和页面必须显示 `providerCode` 与 `methodologyCode`。不同供应商结果分别存储和展示，不直接求和或平均。

### 6.4 资金强度

```text
资金强度 = 窗口内供应商净流入金额 / 窗口内板块成交额
```

用于降低大市值、大成交板块天然金额较大的影响。首屏同时展示原始金额、资金强度和行业排名。

### 6.5 横截面排名与分位

- 排名：在同一市场、同一行业体系、同一窗口内的名次，例如 `3/31`。
- 分位：相对同组其他板块的位置，例如 `92/100` 表示强于约 92% 的比较对象。

`DECISION`：默认展示排名，不显示无标签的百分数。分位只用于高级指标详情和历史位置说明。

### 6.6 流动性

流动性分为三个层级：

| 层级 | 默认指标 | 用户问题 |
|---|---|---|
| 市场 | 总成交额、相对 20 日均值、上涨覆盖率 | 今天市场活跃还是低迷？ |
| 板块 | 成交额占比、占比变化、换手率、成交持续性 | 交易是否向该板块集中？ |
| 个股 | 成交额、换手率、停牌状态、振幅、非流动性估计 | 是否具备正常进出条件？ |

### 6.7 市场广度

市场广度用于判断上涨是否普遍，至少包括上涨/下跌家数、行业上涨比例、板块内部上涨比例和高于中期均线比例。

### 6.8 板块轮动

板块轮动表示资金、成交活跃度和相对收益排名随时间的迁移，不表示货币从一个板块直接转账到另一个板块。

## 7. 产品域一：市场研究

本章只冻结产品职责。市场走势图、流动性与交易活跃度趋势、市场广度、行业成交占比迁移、资金累计走势、相对强弱-动量四象限和板块下钻的详细设计，以 `QTA_V2_INSTITUTIONAL_MARKET_RESEARCH_DESIGN.md` 为准。

### 7.1 市场全景

#### 目标

让用户在一分钟内判断市场环境，而不是直接面对股票列表。

#### 首屏内容

1. 市场成交额及相对 20 日均值。
2. 上涨/下跌家数和行业上涨覆盖率。
3. 流动性状态：活跃、正常、低迷。
4. 资金集中度：前 3/5 行业成交额占比。
5. 数据截至时间、覆盖率、Provider 和质量状态。

#### 输出结论

页面使用证据句描述，不使用无法解释的总分，例如：

```text
市场成交活跃度高于近 20 日均值，交易向电子和有色金属集中；
上涨覆盖率一般，当前属于“局部活跃”，不是普遍上涨。
```

### 7.2 资金与轮动

#### 核心视图

1. 行业资金地图：面积为成交额占比，颜色为资金净额或资金强度。
2. 行业资金池表：成交额、占比、占比变化、净流入、资金强度、连续性、排名。
3. 轮动带：显示每日名次与名次变化，可切换资金、成交活跃度、相对收益和广度。
4. 资金-价格确认矩阵：区分资金价格共振、价格领先、活跃领先和背离。
5. 历史曲线：1/3/5/10/20 日窗口和自定义日期范围。

#### 行业与概念边界

- 默认全市场汇总使用申万一级行业。
- 概念板块作为热点观察单独展示，并明确成分重叠。
- ETF 配置资金作为独立证据，不与行业主动资金流静默相加。

### 7.3 板块研究

板块详情至少包含：

- 行业价格和相对基准走势。
- 资金净额、资金强度和历史分位。
- 成交额占比及其变化。
- 内部上涨覆盖率和龙头集中度。
- 领涨股、资金贡献股、放量股和风险股。
- 数据来源、行业版本、成分有效日期和质量状态。

### 7.4 候选池

候选池是板块研究与策略实验室的连接层。

候选股票必须显示：

- 来源板块和候选日期。
- 入选规则与每条规则的实际值。
- 个股相对板块强弱。
- 流动性和可交易状态。
- 数据质量和风险标签。
- 候选来源：人工、研究模板或已冻结策略。

### 7.5 个股研究

个股研究不替代专业看盘软件。首要任务是把市场背景、板块背景、候选原因和个人交易连接起来。

页面包含：

- K 线、成交量和必要的基础指标。
- 所属行业及行业当前阶段。
- 相对行业、相对大盘表现。
- 个股资金和流动性证据。
- 候选入选原因和失效条件。
- 已有持仓、历史成交、人工计划和复盘标记。

## 8. 产品域二：策略实验室

### 8.1 产品目标

让用户不写代码也能回答：“这个观察规则在历史上是否有用，在哪些市场环境中会失效？”

### 8.2 研究流程

```text
选择研究模板
    → 冻结股票池和历史成分
    → 定义规则、窗口和持有期
    → 生成历史信号
    → 加入交易约束和成本
    → 与基准比较
    → 做样本外和分阶段验证
    → 保存策略版本
    → 生成每日候选
```

### 8.3 第一期研究模板

1. 板块资金与成交共振。
2. 板块持续轮动。
3. 个股相对板块走强。
4. 流动性合格后的放量突破。

### 8.4 历史验证指标

- 信号次数和覆盖年份。
- 1/5/10/20 日后收益分布。
- 年化收益、波动率和最大回撤。
- Sharpe、Sortino、Calmar。
- 胜率、盈亏比和期望收益。
- 换手率、手续费和滑点。
- 相对基准收益、Alpha/Beta 和信息比率。
- 分年度、牛熊阶段和样本外表现。

### 8.5 版本与可重现性

每次研究运行必须保存：

- 数据版本。
- 股票池快照版本。
- 因子和规则版本。
- 参数、持有期和基准。
- 交易成本及市场约束。
- 运行时间、代码版本和结果摘要。

## 9. 产品域三：交易与复盘

### 9.1 产品目标

把研究候选、人工计划、实际成交和复盘归因连接起来，回答实际盈亏来自哪里。

### 9.2 工作流

```text
市场/策略候选
    → 人工确认
    → 交易计划
    → 实际成交与持仓
    → 盘后复盘
    → 策略归因 + 执行归因
```

### 9.3 复盘归因

每笔交易至少回答：

1. 市场和板块方向判断是否正确。
2. 候选规则是否持续有效。
3. 买入、加仓、减仓和卖出时机是否符合计划。
4. 仓位和风险限制是否遵守。
5. 盈亏属于策略问题、数据问题还是人工执行偏差。

## 10. 产品域四：数据中心

### 10.1 产品目标

把当前散落的行情工作台、板块管理、行情数据和行情资产统一为数据资产控制台。

### 10.2 数据资产目录

每个数据集展示：

- 数据集名称与业务用途。
- 市场、证券范围和频率。
- Provider、数据集版本和权限状态。
- 历史起止、水位和预计更新时间。
- 总记录数、存储量和覆盖率。
- 缺失、重复、异常、陈旧和冲突状态。
- 被哪些研究、因子和策略使用。

### 10.3 三类采集流水线

#### 全市场日频增量

交易日收盘后依次采集交易日历、证券状态、股票/指数/ETF 日线、行业分类、行业成分、板块行情和资金流。

#### 重点标的盘中采集

只对持仓、自选、候选池和重点 ETF 采集分钟数据；严格使用对应市场交易时段。

#### 历史回补

按 Provider、数据集、市场、范围、频率和日期创建任务，支持分片、限流、暂停、续跑、重试和缺口补齐。

### 10.4 数据处理状态

```text
计划中 → 已领取 → 获取中 → 原始数据已落库
→ 标准化完成 → 质量通过 → 已发布 → 衍生计算完成
```

失败任务保留失败阶段、错误分类、重试次数和最后成功水位。

### 10.5 发布规则

- 新批次未通过质量校验时，不替换上一个已发布版本。
- 页面必须区分空数据、延迟数据、陈旧数据、权限不足和 Provider 故障。
- 研究页面只读取已发布版本。
- 数据修复后允许按原版本参数重算衍生指标和研究结果。

## 11. 数据规划

### 11.1 数据层次

| 层次 | 内容 |
|---|---|
| 原始事实层 | Provider 原始行情、资金流、行业、成分和元数据 |
| 标准数据层 | 统一证券、市场、币种、时区、复权和行业版本 |
| 特征因子层 | 收益、动量、波动、流动性、资金、广度和相对强弱 |
| 研究结果层 | 股票池、信号、回测、策略版本和每日候选 |
| 个人行为层 | 计划、成交、持仓、账本和复盘 |

### 11.2 第一阶段历史范围

- A 股全市场日线：2021-01-01 至今。
- 申万行业、历史行业成分、行业和概念资金流：2021-01-01 至今。
- 主要指数和 ETF：2021-01-01 至今。
- 重点证券分钟线：先保留 6 至 12 个月，按存储和配额评估扩展。
- 数据质量稳定后，再把日频历史扩展至 2016 年。

### 11.3 Provider 分工候选

| Provider | 初步职责 | 状态 |
|---|---|---|
| Longbridge | 实时行情、重点证券分钟线、个股级行情与资金能力 | 已有适配，权限需持续可观测 |
| Tushare | A 股全市场历史日频、行业、历史成分、行业/概念资金流 | `ASSUMPTION`，需先验证账号积分、授权与数据质量 |
| CSV/本地导入 | 外部授权数据和故障期间的可控补录 | 已有日 K 基础，需统一数据集契约 |

## 12. 关键数据对象

V2 至少需要以下领域对象，具体表结构在架构设计阶段冻结：

- `DatasetDefinition`：数据集定义和用途。
- `DatasetVersion`：数据版本、水位和发布状态。
- `CollectionPlan`：持续采集规则。
- `BackfillRequest`：历史回补请求。
- `CollectionRun/Chunk`：任务执行与分片。
- `DataQualityResult`：覆盖率和异常结果。
- `SectorTaxonomy/SectorMembership`：行业体系和 point-in-time 成分。
- `SectorFlowFact`：供应商口径资金事实。
- `SectorActivityFact`：成交额、占比、换手和市场广度。
- `UniverseSnapshot`：历史股票池快照。
- `FactorDefinition/FactorValue`：因子定义和结果。
- `ResearchExperiment/BacktestRun`：研究和回测运行。
- `StrategyVersion/CandidateSnapshot`：冻结策略和每日候选。

## 13. 页面解释规范

所有金融指标必须支持查看：

1. 这个指标回答什么问题。
2. 使用什么公式和时间窗口。
3. 数据来自哪里、何时更新。
4. 数值高低通常如何理解。
5. 哪些情况下可能失真或不可比较。

默认页面只展示金额、排名、变化、状态和证据句；专业公式通过指标详情展开，不在首屏堆叠。

## 14. 空状态、错误状态与质量状态

| 状态 | 页面行为 |
|---|---|
| 无采集计划 | 引导进入数据中心创建对应数据集计划 |
| 历史不足 | 显示所需最小历史和当前覆盖范围，不计算长期结论 |
| 数据陈旧 | 保留最后合格结论并显示截至时间，不伪装实时 |
| 部分缺失 | 显示覆盖率，阻断需要完整横截面的排名和回测 |
| Provider 无权限 | 显示缺少的数据集和权限，不回退为其他金融含义 |
| Provider 故障 | 记录失败、自动退避，继续使用上一个发布版本 |
| 口径不可比 | 禁止跨 Provider、跨币种或跨分类体系聚合 |

## 17. V2 MVP 验收标准

### 数据

- A 股日频历史覆盖 2021 年至今，预期交易记录覆盖率达到冻结阈值。
- 行业成分具备纳入和剔除日期，可按历史日期还原。
- 每个资金事实可追溯 Provider 和方法口径。
- 缺口、陈旧、重复和权限不足不会被标为正常。

### 市场研究

- 用户能在一屏内回答市场是否活跃、交易集中在哪里、主动资金偏向哪里、方向是否持续。
- 行业池同时展示成交额、占比、净流入、资金强度、排名和连续性。
- 概念板块不会被汇总成全市场资金总额。
- 任一研究结论可查看数据来源、截至时间、覆盖率和计算证据。

### 策略实验室

- 至少一个模板完成股票池、信号、成本、基准和样本外历史验证。
- 同一数据版本和参数可以重现相同结果。
- 回测包含 T+1、手续费、滑点、停牌和涨跌停约束。

### 交易与复盘

- 每个人工计划可以关联市场证据、候选来源和策略版本。
- 复盘可以区分策略有效性和人工执行偏差。

## 18. 实施门禁、延期决策与假设

- `IMPLEMENTATION_GATE`：MR-0 必须验证 Tushare 账号是否具备行业、概念资金流和历史分钟数据所需积分与授权；未通过时不得承诺对应覆盖范围。
- `IMPLEMENTATION_GATE`：行业资金流 Provider 必须比较覆盖率、稳定性、授权和口径后通过 ADR 决定；实现者不得把同花顺、东方财富或其他口径静默混用。
- `DEFERRED_DECISION`：ETF 份额变化不进入 MR-1；是否作为 V2-2/V2-3 的配置资金证据，在基础资金事实 PoC 后单独冻结。
- `ASSUMPTION`：V2 MVP 以盘后日频研究为主，盘中研究只覆盖重点标的，不建设全市场实时资金系统。
- `ASSUMPTION`：现有数据库迁移采用增量表和兼容性改造，不删除已落库行情和交易数据。
